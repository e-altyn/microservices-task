# Проектное домашнее задание

- Выполнил: Алтынников Егор, группа 420
- Тема: Прогнозирование дефолта кредитополучателей (классификация на датасете Lending Club)

Реализовано 5 микросервисов:
1. **Collector** — загрузка данных
2. **Storage** — хранение данных
3. **ML Service** — обучение, прогнозирование и оценка качества
4. **Web Master** — единый API и координация сервисов
5. **Visualization** — веб-интерфейс пользователя

## Запуск

Все команды ниже выполняются из корня репозитория. Нужен работающий Docker с Compose v2 и свободные порты 8000/8080.

```bash
# Запуск
docker compose up --build -d --wait
```

```bash
# Посмотреть состояние сервисов
docker compose ps

# Посмотреть последние 100 строк логов каждого сервиса
docker compose logs --tail=100

# Остановить систему, сохранив данные и модели
docker compose down

# Для повторного запуска:
docker compose up -d --wait
```

- Интерфейс: <http://localhost:8080>
- Состояние сервисов: <http://localhost:8000/api/system>
- Документация API Web Master: <http://localhost:8000/docs>

## Сценарии работы

1. **Загрузка данных.** В разделе "Данные" можно загрузить батч. Collector выдаст 1000 строк, Web Master сохранит их в Storage. Можно посмотреть первые строки, переименовать или удалить батч.
2. **Обучение модели.** Предлагается выбрать сырые данные и алгоритм. Далее выбрать имя модели и нажать "Создать и обучить". ML Service разделит данные на train/test, обучит предобработку и модель, сохранит модель и подготовленный датасет.
3. **Прогноз.** Предлагается выбрать обученную модель и источник "Загруженный батч", затем нужный сырой датасет. Для проверки на новых данных можно выбрать другой батч, чем при обучении. Можно также выбрать свой CSV-файл. Результат (вероятность и метка дефолта для каждой строки) отображается в таблице. Максимум — 1000 строк и 2 МБ для CSV. Колонка `loan_status` не используется для прогноза.
4. **Оценка модели.** Предлагается выбрать модель в последнем разделе и увидеть описание, размеры выборок, ROC AUC, accuracy, precision, recall и матрицу ошибок. Эти результаты доступны после перезапуска контейнеров.

Автоматическая демонстрация выполняет те же четыре сценария через API и сохраняет новый датасет и модель. Нужен только Python 3 со стандартной библиотекой:

```bash
python3 scripts/demo.py # --url http://localhost:8001 для своего порта
```

## Данные и модель

Включена подвыборка из 10 000 записей (8028 Fully Paid, 1972 Charged Off). Подробности в [data/README.md](data/README.md).

Доступны два алгоритма: Logistic Regression и Random Forest. Для обоих используются пять числовых и три категориальных признака. Отсутствующие значения заполняются; числовые признаки масштабируются, категории кодируются one-hot. Все обучаемые преобразования подгоняются только на train-части. Категории, которых не было при обучении, поддерживаются.

Положительный класс — Charged Off, отрицательный — Fully Paid, другие исключаются. Порог метки — 0.5.

## Устройство

```text
Браузер -> Visualization -> Web Master
                            ├── Collector -> CSV (только чтение)
                            ├── Storage -> SQLite (сырьё и подготовленные данные)
                            └── ML Service -> файлы модели и summary
                                └── Storage API
```

У каждого сервиса есть свой контейнер, Python-приложение, Dockerfile, requirements и JSON-конфигурация. Только GUI и Web Master публикуют порты на localhost. Файловая система Storage не доступна ML напрямую, модели принадлежат ML Service.

- `services/` — пять сервисов
- `common/` — общие схемы и обработка сетевых ошибок
- `scripts/` — подготовка данных и демонстрация
