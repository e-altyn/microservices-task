# Документация системы

## Постановка задачи

Система поддерживает эксперимент по классификации исторических кредитов Lending Club: по параметрам кредита и заемщика определить вероятность класса Charged Off. Целевой пользователь — исследователь/аналитик, которому нужны загрузка данных, воспроизводимое обучение, пакетный прогноз и отдельный просмотр качества.

Доступны Logistic Regression и Random Forest. Алгоритм выбирается при создании модели; оба используют общую предобработку, обучение и API прогноза. Состав признаков фиксирован, поэтому случайно переданные колонки с платежами после выдачи кредита не попадут в модель.

Четыре сценария: загрузить данные, обучить модель, получить прогноз и оценить обученную модель. Пошаговые инструкции приведены в README.

## Ответственность сервисов

**Collector** читает заранее подготовленный CSV и возвращает батч по номеру. Состояния «следующего батча» на сервере нет: клиент явно выбирает номер. Это позволяет повторить загрузку после сетевой ошибки. Действия записываются в `var/collector/downloads.log` в отдельном томе. Сырые записи сохраняются без нормализации признаков.

**Storage** владеет SQLite-базой. Таблица `datasets` хранит идентификатор, имя, тип raw/processed, источник, признак синтетических данных, время создания, число строк и JSON записей. Поддерживается полный CRUD объектов датасета: создание, список/чтение, изменение имени, удаление. Содержимое набора после создания не меняется; изменение состава данных оформляется новым набором. SQL-запросы параметризованы. SQLite не требует шестого контейнера и достаточен для небольшого учебного проекта.

**ML Service** получает сырой датасет через HTTP API Storage. Подготовка выбирает восемь фиксированных признаков, приводит числа (в том числе строки с `%`) и категории к единому представлению, пустые и некорректные числовые значения трактует как пропуски. При обучении отбираются два целевых статуса. Числа и категории обрабатываются внутри sklearn Pipeline: медианная импутация и StandardScaler для чисел; заполнение `unknown` и OneHotEncoder с поддержкой неизвестных категорий — для категорий. Все параметры обучаются только на train-части.

ML Service сохраняет в Storage нормализованный снимок с `target` и `partition=train/test`. Обученная предобработка вместе с классификатором хранится в joblib, summary и метрики — в JSON собственного тома. Модель создается явно, затем обучается. Повторное обучение успешно обученной модели не допускается: для следующего эксперимента создается отдельный объект. Автоматического управления версиями нет.

**Web Master** предоставляет единый API сценариев. Он переносит батч Collector в Storage, создает модель и передает команды обучения/прогноза в ML Service. Чтение датасетов и метаданных также проходит через него. Для прогноза можно выбрать уже загруженный сырой батч: Web Master читает его из Storage и передает только восемь входных признаков в ML, исключая целевую переменную и служебные поля. Multipart-загрузка CSV преобразуется в список записей перед передачей в ML. Прогноз не изменяет датасет и не переобучает модель.

**Visualization** отдает HTML/CSS/JavaScript, минимальный health API и проксирует `/api/*` в Web Master. Браузеру достаточно одного адреса, CORS не требуется. Интерфейс использует текстовые DOM-операции для результатов и не вставляет пользовательские поля как HTML.

## Обучение и оценка

Алгоритмы: LogisticRegression (max_iter=1000) и RandomForest (n_estimators=100, max_depth=8, min_samples_leaf=5). Для обоих random_state=42 и class_weight=balanced. Параметры Random Forest заданы в секции random_forest конфигурации ML. Масштабирование чисел сохраняется в общей предобработке. При одинаковом датасете и конфиге оба алгоритма используют одно и то же разбиение train/test. Веса классов рассчитываются по train-части, разбиение — 75/25 со стратификацией. Батч по умолчанию содержит 1000 строк. Предобработка и модель подгоняются на train, метрики вычисляются на test; дополнительного выбора алгоритма/параметров по test нет.

Метрики:

- ROC AUC — качество ранжирования вероятностей.
- Accuracy — доля верных ответов при пороге 0.5.
- Precision и recall для класса Charged Off. При отсутствии положительных прогнозов precision принимается равной 0.
- Матрица ошибок: строки — истинные классы 0/1, столбцы — предсказанные 0/1.

Состав классов несбалансирован; accuracy без ROC AUC и recall недостаточно для оценки. Разбиение случайное, не временное. Модель не проверяется на будущих периодах. Выборка случайно отобрана из полного исходного файла среди кредитов со статусами Fully Paid и Charged Off. Другие статусы исключены, поэтому результаты нельзя распространять на весь портфель. Источник и точный состав выборки описаны в `data/README.md`.

## API

Пути внутренних API указаны относительно соответствующего сервиса. У каждого сервиса есть `GET /health` и автоматически генерируемые `/docs`, `/openapi.json`. Из хоста опубликован только API Web Master; остальные доступны внутри сети Compose.

| Сервис | Метод и путь | Действие |
| --- | --- | --- |
| Collector | GET /batches/{number} | Батч с источником, количеством батчей и записями |
| Storage | POST /datasets | Создать raw/processed датасет |
| Storage | GET /datasets | Список метаданных без записей |
| Storage | GET /datasets/{id} | Датасет с записями |
| Storage | PATCH /datasets/{id} | Изменить имя |
| Storage | DELETE /datasets/{id} | Удалить, ответ 204 |
| ML | POST /models | Создать необученную модель |
| ML | GET /models | Список моделей и summary |
| ML | GET /models/{id} | Состояние и метрики |
| ML | POST /models/{id}/train | Обучить; JSON: dataset_id |
| ML | POST /models/{id}/predict | Прогноз; JSON: records |
| Web Master | GET /api/system | Доступность Collector, Storage, ML |
| Web Master | POST /api/datasets/collect | Загрузить и сохранить; JSON: batch_number |
| Web Master | GET, POST /api/datasets | Список/создание датасета |
| Web Master | GET, PATCH, DELETE /api/datasets/{id} | CRUD через Storage |
| Web Master | GET, POST /api/models | Список/создание модели |
| Web Master | GET /api/models/{id} | Summary |
| Web Master | POST /api/models/{id}/train | Обучение выбранного dataset_id |
| Web Master | POST /api/models/{id}/predict | Прогноз по JSON records |
| Web Master | POST /api/models/{id}/predict-dataset | Прогноз загруженного сырого батча; JSON: dataset_id |
| Web Master | POST /api/models/{id}/predict-csv | Multipart-поле file с CSV |
| Visualization | GET / | Интерфейс |
| Visualization | /api/* | Прокси к Web Master |

Создание датасета: `name`, `kind` (raw по умолчанию), `source`, `is_synthetic` и массив `records` (1–10 000 строк). Создание модели: `name` и `algorithm` (`LogisticRegression` по умолчанию или `RandomForest`). Алгоритм сохраняется в summary; изменить его после создания нельзя. Обновление датасета: `name`. Предсказание: `records` (1–1000 строк); обязательны все восемь входных колонок, сами значения могут быть пустыми. В ответе массив `predictions`: номер входной строки с 1, вероятность, метка. Дополнительные колонки, включая таргет, не используются в прогнозе. Для `predict-dataset` передается `dataset_id`; набор должен иметь тип raw и не более 1000 строк. Ответ дополнительно содержит `dataset_id` и `dataset_name`. Строки не обрезаются: превышение лимита дает 422. Выбор батча для прогноза не означает независимую оценку качества, если этот же батч использовался для обучения.

Пример последовательности из терминала:

```bash
curl -X POST localhost:8000/api/datasets/collect \
  -H 'Content-Type: application/json' -d '{"batch_number":1}'
curl -X POST localhost:8000/api/models \
  -H 'Content-Type: application/json' -d '{"name":"Первый эксперимент"}'
# Подставьте id из двух предыдущих ответов:
curl -X POST localhost:8000/api/models/MODEL_ID/train \
  -H 'Content-Type: application/json' -d '{"dataset_id":"DATASET_ID"}'
curl localhost:8000/api/models/MODEL_ID
```

## Конфигурация и хранение

У каждого сервиса есть `services/<name>/config.json`. Compose монтирует конфигурации только для чтения. JSON содержит host/port и специфические параметры:

| Сервис | Параметры |
| --- | --- |
| Collector | source_path, source_name, is_synthetic, batch_size, max_source_rows, log_path |
| Storage | database_path |
| ML | storage_url, artifact_dir, request_timeout, test_size, random_state, max_iter, class_weight, min_training_rows, random_forest |
| Web Master | collector_url, storage_url, ml_url, request_timeout, max_upload_bytes |
| Visualization | master_url, request_timeout, max_request_bytes |

Пути относительны рабочему каталогу `/app` в контейнере. `data/` смонтирована Collector только для чтения. Именованные тома Compose хранят БД, ML-артефакты и лог Collector. Для внутреннего порта, отличного от 8000, нужно согласованно изменить адреса зависимостей и отображения портов Compose. Внешние порты задаются `.env` и не влияют на внутренние адреса.

Для локальных отдельных процессов можно задать переменную `CONFIG_FILE` с путем к альтернативной JSON-конфигурации и запустить `python -m common.run collector` (аналогично storage/ml/web_master/visualization). При этом нужно самостоятельно задать разные порты и локальные адреса зависимостей. Рекомендуемый способ запуска — Compose.
